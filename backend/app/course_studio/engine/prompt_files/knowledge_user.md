### 一、粒度与合并原则（偏宽泛、重整合、防碎片化）
1. **聚焦可考核、可学习的核心模块**：每节整合为 **2～5 个核心考点**，每个考点代表一个完整的核心概念、语法机制、编程方法或算法原理。
2. **同类细项合并，独立机制单列**：
   - **应合并的碎片**：不要把并列的基础类型、单个运算符、同类内置方法或历史枚举拆成零散知识点。例如：不要把「int」「float」「bool」拆成 3 个，应合并为「基本数据类型」；不要把「+」「-」「//」「%」逐个单列，应合并为「算术运算符与优先级」；不要把单页案例步骤或操作截图零碎单列。
   - **应保持独立的考点**：核心数据结构与独立运行机制应分开建点（如「字符串索引与切片」「字符串常用方法」「字符串格式化」或「列表操作」「字典与集合」按讲授篇幅各自独立）。
3. **非考点页面不硬凑**：封面页、目录页、章节过渡页、纯软件安装/界面截图页、单题展示页、小结/致谢页若没有新核心考点，不要强行造点或硬塞进相邻考点。

### 二、命名与字段规范
1. **`name`（知识点名称）**：
   - 长度严格控制在 **3～12 个字**，为简洁规范的名词短语，不写成完整句子。
   - **严禁带任何章节号或序号前缀**（如 `1.1`、`3.2`、`一、`、`（1）`）。
   - **严禁用括号罗列子项或补充说明**（例如不要写「字符串基本操作（索引、切片、操作符）」「字符编码（ASCII、Unicode）」，应简明写成「字符串索引与切片」「字符编码体系」）。
   - **严禁空泛标题**：不要使用「概述」「简介」「本节内容」「小结」「基础知识」等无区分度词，应写具体主题名（如「变量命名与赋值规则」「程序输入与输出」）。
2. **`pages`（出处页码）**：
   - 只能使用下方「逐页讲义」中真实出现过的页码整数，按升序排列。
   - 连续多页围绕同一考点展开（含概念讲解 + 配套例题）时，合并归入该考点的 `pages` 列表。
   - 若某考点只在目录或小结提及而未展开，则 `pages` 填空数组 `[]`。
3. **`brief`（核心机制 + 典型易错点）**：
   - 用一句话凝练概括该考点的**核心机制与 1 个初学者常见易错点**，严格控制在 **55 字以内**（例如：「按字符集移除字符串两端指定字符，初学者易误以为删除整段子串」）。
4. **`section`（归属节号）**：
   - 必须原样使用下方「本章结构」中的节号，不可新造节；同一考点在整章只保留一次，按课件讲授先后顺序排列。
