以下 8 条为自动沙箱验题硬性红线（违反任意一条将被自动拒收）：
1. **严守教学大纲，绝不超纲**：`reference_solution` 与 `starter_code` 仅允许使用当前章节材料及补充语法约束内已讲授的语法、内置函数与标准库；若本章尚未讲授 `if`/`for`/`while`/`def`/`class`/列表推导式等结构，绝对禁止使用。
2. **标准输入输出契约**：所有输入严格来自标准输入 `stdin`，必须使用无参数的 `input()` 配合 `int()` / `float()` / `input().strip()` / `input().split()` 等显式转换读取（**严禁**写 `input("请输入：")` 等带提示语的参数，也**严禁**照搬课件里的 `eval(input())` 写法）；所有输出严格使用 `print()` 打印到标准输出 `stdout`。
3. **沙箱安全与确定性**：严禁文件读写 `open()`、严禁动态执行 `eval()`/`exec()`/`compile()`/`__import__()`、严禁导入系统/网络/第三方库（如 `os`、`sys`、`subprocess`、`socket`、`pathlib`、`requests`、`numpy`、`tkinter` 等）、严禁依赖当前系统时间；若确实考查 `random`，必须在题干写明并固定 `random.seed(...)`。
4. **微场景包装与 100% 题干自包含**：
   - 尽量用 2–3 句简洁真实的教学微场景包装问题（如阶梯计费、考勤统计、折扣核验、日志清洗、成绩分档、传感器过滤），避免千篇一律的「输入两个整数 a 和 b」；
   - `prompt` 必须清晰分段包含 `【题目描述】`、`【输入格式】`、`【输出格式】`，把输入行数、同行分隔符、数据类型、数值范围、保留小数位与大小写要求写到毫无歧义（须让第三方仅看题干与公开样例即可独立写出完全一致的程序）；
   - 严禁出现「见课件第 X 页」「如图所示」「如下表」「上述代码」等悬空引用。
5. **难度与作答形式严格解耦**：程序填空（`fill_code`）、程序改错（`debug`）、程序设计（`design`）是作答形式，难易度（`易`/`中`/`难`）独立于形式；「难」的填空或改错题应考查高思维密度的核心表达式、条件边界或隐蔽逻辑错误，不可将填空等同于简单题。
6. **初始代码有效性**：
   - `fill_code`：`starter_code` 与 `reference_solution` 在 `# === 填空区 N 开始 ===` / `# === 填空区 N 结束 ===` 标记之外的每一行必须逐字符完全一致，且 `starter_code` 无法通过全部测试用例；
   - `debug`：`starter_code` 须定向植入会改变运行结果或引发报错的实质性学生常犯错误（严禁只改注释、变量名或等价写法），且至少在 1 组公开样例及若干隐藏用例上被真实触发、导致运行报错或输出错误。
7. **五类边界用例全覆盖**：提供 **3 组公开样例（`samples`）** 与 **5 组隐藏用例（`hidden_cases`）**（所有 8 组输入互不重复，且均以合理换行 `\n` 结尾）。5 组隐藏用例须覆盖：① 常规典型值；② 零值/空串/单元素边界；③ 临界相等阈值（如恰好达到分界线）；④ 负数或较大极值；⑤ 易错格式/精度/首尾空白或大小写边界。先用 `reference_solution` 精确推导每组 `expected_output`。
8. **阶梯教学辅助与纯净结构化解析**：`hints` 给 2–3 条由浅入深的分步提示（不泄露完整答案）；`explanation` 控制在 **70–220 字**，用纯文本换行按 `解题思路：…\n关键细节：…\n易错提醒：…` 三行写出（禁用 `**`、`###`、三反引号等 Markdown 符号，改错题先点明原代码错误根因），严格客观第三人称，严禁引用页码/课件字样，严禁出现任何推演反问或自我纠错独白。
