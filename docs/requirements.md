# 已确认需求

本文件保存当前约束与稳定编号，细节由对应规范维护；不记录逐轮执行、个人环境状态或一次性操作授权。最新明确决定优先，未确认建议不作为要求。修改规则时原位更新，维护方式见[文档索引](README.md#文档维护)。

## 教学、测验与脚本

| 编号 | 当前约束 | 规范归属 |
| --- | --- | --- |
| LEARN-01 | 阅读、练习、测验等是活动；任务定义要完成的目标与依赖，剧情组织人物回应和活动进出。教师通过可视化流程与任务编辑器维护当前定义；YAML/JSONL作为课程交换格式，仍可显式校验导入。 | [架构](architecture.md)、[内容配置](content-authoring.md) |
| LEARN-02 | YAML 可配置整份或指定页范围阅读、视频最低有效观看时长、重点页和重点片段。后端统一验证与累计证据，跳页、拖动播放位置不能冒充完成。 | [内容配置](content-authoring.md)、[HTTP 契约](api-contract.md) |
| LEARN-03 | 学习目标展示真实阅读、练习或观看进度；阅读位置与目标完成度分开，参与记录不称为知识掌握率。保留原主线指定页与已有学习证据。 | [游戏设计](design/game-interface.md)、[产品](product.md) |
| LEARN-04 | 练习只用单题模式，提供上一题、下一题和侧栏目录跳转；每题“提交答案”，错误可改正后重新提交，跳题保留各题草稿和反馈。 | [游戏设计](design/game-interface.md)、[内容配置](content-authoring.md) |
| LEARN-05 | 单元测验支持单题与整卷两种排版，共用答案；全部作答后从题目目录上方统一交卷。交卷后服务器锁卷，展示逐题对错，不能修改或绕过整卷接口逐题提交。 | [HTTP 契约](api-contract.md)、[游戏设计](design/game-interface.md) |
| LEARN-06 | 测验满分 100，按 `correct_count * 100 // total` 向下取整；未判完为 `null`，不能显示成 0 分。所有题目真实判定结束即完成测验，全对另行表示；错误答案不阻断一次性测验剧情，基础设施故障不算答错。 | [产品](product.md)、[HTTP 契约](api-contract.md) |
| LEARN-07 | NPC 可按目标、任务、章节状态与真实测验分数回应；镇长结束回复区分成绩。条件组合、入口、分支与选项均受限并在服务端鉴权，显示过的选项提交时也要复验。 | [内容配置](content-authoring.md)、[架构](architecture.md) |
| LEARN-08 | 任务结束后仍可进行脚本日常聊天，条件满足时出现更多选项。日常独立于任务，复用演出引擎；随机结果落入会话，恢复与幂等重试不重抽。当前 NPC 的可执行教学和等待活动优先；闲聊不新增任务、学习或成绩记录、世界解锁标记及 AI 调用。 | [内容配置](content-authoring.md)、[架构](architecture.md) |
| LEARN-09 | 测验Python提交通过独立go-judge容器执行；练习提交在浏览器重新评测全部公开样例，后端校验回传结果、幂等保存完成记录，不进入judge队列。go-judge与db/api/web统一部署，任务使用现有数据库持久队列。API主机不执行学生代码，隐藏用例不外泄；未知派发先对账，旧成绩不重评。 | [架构](architecture.md)、[部署](development.md#可选服务与配置) |
| LEARN-10 | 教师从课程的一个章节选择多个知识点，对每个目标设置答对总数、各题型最低数量或两者组合。按学生抽取满足全部目标的首批题；多知识点题只分配给一个目标，发布校验与抽取均全局去重。 | [内容配置](content-authoring.md#练习与一次交卷测验) |
| LEARN-11 | 首次正式答错一题时，从同一目标剩余题池追加一道新题。学生可立即修改并重新提交，同一题重复答错不再追加。 | [内容配置](content-authoring.md#练习与一次交卷测验) |
| LEARN-12 | 个人题单在重进时恢复；每次补题增加题单总数。所有知识点达标且个人题单全部通过才完成，包括追加题与错题订正。任务与剧情使用同一服务端证据。 | [游戏设计](design/game-interface.md#练习与单元测验) |
| LEARN-13 | 教师编辑交互练习题的 HTML、CSS、JS，在预览中试答并查看助教状态。编辑器保存时试跑脚本，可用题须通过校验。仅练习可选用，学生在卡片内操作、提交或重置本题草稿。服务端核对实际提交值后记录判定。 | [编写指南](interactive-practice-authoring.md)、[HTTP 契约](api-contract.md) |

| ADMIN-06 | 影响互动或任务的保存须先预览并确认，按班预览并重置本课程受影响状态；保留阅读、作答、成绩与无关任务，包导入仍遵守证据保留规则。知识点练习限一个章节，其他活动可选择同班课程的多章知识点。 | [后台规范](design/teacher-interface.md)、[接口契约](api-contract.md#teachers-and-authoring) |
| ADMIN-07 | 教师可按日期查询本班服务器Python评测和授权诊断，排除练习浏览器提交，管理员可检测、暂停和恢复全站派发。实时队列不受历史筛选影响；未知派发先对账，不伪造诊断、不重判旧成绩。 | [后台](design/teacher-interface.md#评测管理)、[接口](api-contract.md#评测管理) |
| ADMIN-08 | 新课程快速编排使用「学课件、做练习、做测验」。教师先确认模板与可选功能，再选择授课章节、课件和知识点，设置各章练习、测验总数或按知识点与题型分配，预览后生成。沿用课程默认的环节在题量不足时自动下调，单独指定题量不足或环节无题时提示教师处理。生成的角色、地图交互、活动、任务和对白使用现有游戏引擎，仍可在快速编排或教学流程中调整。 | [内容配置](content-authoring.md#按模板快速编排)、[后台](design/teacher-interface.md#快速编排) |
| ADMIN-09 | 教师指定起始章，可选择最终章或留待续编。起始章由三位角色逐步引导，普通章依授课顺序使用十套熟人对白，最终章在测验后回顾整门课程。教师可在中间插章。镇长、图书管理员及练习场教练在各自室内接待学生。课间闲聊和书架支线可以独立启用。书架属于全镇，起始章阅读完成后开放，学生可在后续章节完成；书架始终可查阅学习资料。 | [模板与对白](content-authoring.md#按模板快速编排) |
