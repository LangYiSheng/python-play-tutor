# 内容配置与发布

本页维护课程格式和内容规则，操作步骤见[开发手册](development.md#目录课程包操作)，教学约束见[需求](requirements.md)。

## 章节任务点

教师在课程内容的章节详情上传或关联资料，在学习任务页选择章节后设置必读资料、客观题练习、编程题练习和测验。同一资料在每个章节分别设置是否必读及阅读要求。普通必读课件默认读完每一页，高级设置可用指定范围或任意不同页数，并可组合有效阅读时长。视频使用有效播放时长及指定片段。后台标签页暂停阅读计时。

章节按班级开放，可以暂停或定时开放。就绪的资料在已开放章节中可读。本章所有必读资料达标后，两类练习可同时进行。选做练习不参与章节完成计算。所有必做练习完成后可进行本章各份测验，全部试卷判定完毕即完成测验阶段。教师后续添加要求时即时重算可做范围，保留已提交的证据、草稿和成绩。

## 统一教学角色与素材

图书管理员、教授、教练和镇长分别负责学习资料、客观题练习、编程练习和测验。位置和职责固定，名称、人设、立绘和像素角色由平台管理员统一维护。学生答疑默认开启，前三位分别负责本环节，测验期间关闭答疑。进出工作区的对白使用固定文本及实时任务进度。

## 媒体与安全

文本使用 UTF-8，PDF 支持私有阅读，MP4/WebM 支持鉴权文件流和 Range。演示文稿的页面预览由隔离转换服务生成。未配置转换服务时，有可提取正文的 PPTX 可以按页显示文字并记录阅读进度。演讲者备注仅供教师预览和讲稿创作。PPT 及无法提取正文的 PPTX 需要转换服务。上传替换会更新同一个资料 ID，各章节继续使用该资料。

私有材料应留在鉴权存储中。隐藏答案不进入题干、公开样例和学生助教上下文。

## 课程包PDF与视频导入

本节说明课程43可信媒体来源的核验规则；当前班级从 格式 4 完整目录包导入，不通过来源媒体 CLI 直接覆盖班级数据。操作见[开发手册](development.md#格式-4-课程导入班级)。

专用CLI `python -m app.course_media <archive.tar.gz> --source-root <可信课程目录>` 接入用户提供的课程包43媒体，只更新当前Material和私有文件，不调用seed、不创建Activity/Quest，也不修改学生阅读、任务、提交或成绩。无需新增数据库迁移。

7份PDF原位绑定材料186..192，保留现有content.pages中的561个原页面ID、页码、标题和提取文本，类型改为pdf。当前第一章仍使用材料186及原全局页10715/10723/10724（第34/42/43页）；提取文本继续用于检索和引用，界面展示真实PDF整页，不向学生展示提取文本。普通上传会重新生成页ID，不能替代此专用导入。

按章节关联导入的视频默认选读。教师可在学习任务页设置为必读并指定观看条件。学生读取资料和媒体时，服务端校验班级成员身份和章节开放状态。

导入器先完整检查路径/链接/重复成员、文件与总量、源清单、PDF页数和原页面ID、MP4文件签名及34份SHA256，再将文件写入私有存储并事务更新材料。可信清单由显式source-root目录提供，不内嵌镜像，不能由待导入媒体包内清单任意替换。当前文件使用内容哈希存储键，同键对象校验一致时复用，不一致时拒绝覆盖；数据库失败回滚，未引用文件不会发布。该CLI用于管理员导入已核查课程包，不是公共的任意归档上传端点。

原包有43个文件，压缩884347179字节、解压文件总量919211590字节：7PDF、34MP4和两份清单/字幕JSON，无PPT/PPTX。PDF页数45、73、98、74、105、50、116，合计561。视频分章3/2/10/4/4/4/7，总标注时长32384秒（约9小时）。清单及字幕与仓库已有JSON一致；全部kcCodes为空，字幕为machine_generated_unreviewed。此次不会自动建立知识点级视频映射或把字幕接入助教，更不会用机器字幕当标准答案。

## 练习与一次交卷测验

全部作答后，学生可在右侧题目列表下交卷，随后回到小镇查看镇长反馈。

测验试卷模式中的编程题使用紧凑摘要，仅保留题名、题干、作答状态和通过数量；编辑器、样例与详细反馈在单题模式显示。摘要按钮切换并定位对应题，保留草稿；已交卷仅可查看详情。公开样例不计成绩，代码修改后标记上次运行结果；正式判题未知或服务故障不显示为全部未通过。

知识点练习在一个章节内选择目标。每个知识点可以设置答对总数、按题型设最低数，或组合设置。例如“答对 3 题，含至少 1 道编程题”，编程题同时计入总数。发布时按所有目标一同校验本班可用题库能否分配足够的不同题目。编程练习需要至少一个公开样例供浏览器评测。一道多标签题只能分给一个目标。固定题单练习按教师选定的题集和顺序逐题通过。

学生首次进入时抽取能覆盖目标的个人题单。某题首次答错时，在同一目标下优先按欠缺题型追加一道尚未分配的题。每道题最多触发一次补题。学生答错后可以立即订正。分子是不同已通过题数，分母包括初始题和所有追加题。所有目标达标、所有已分配题都通过后才完成。

`kind: assessment` 使用教师指定的已审核题集，允许单题或整卷浏览，但只能填写完整后一次“提交试卷”。单题布局与整卷布局只是同一份答案的两种显示方式，切换布局不创建新考核或清空草稿。

测验草稿按学生、班级、活动持久化，revision仅防并发草稿覆盖，不是内容版本。正式交卷在一个事务中锁定答案并建立每题判定记录，随后不可改答案、重新交卷或再运行不同代码。成绩统一满分100分，使用整数公式 `答对题数 × 100 // 总题数`，始终向下取整：三题答对一题33分、两题66分、全对100分；未完全判定时score为null，不冒充0分。正确题数/总题数保留，旧Submission不改写或重判。隐藏答案和私有用例不进入学生响应。Python题仍只通过go-judge判定，状态未知时不盲目重发。

已交试卷的每道题都获得学术判定后，该份测验即完成。`passed` 单独表示是否全部答对。待判定和评测异常的试卷继续只读，等待后台判定或对账。

升级到章节任务点时清除旧版测验作答及成绩。新版已交试卷使用原有题集，新增的独立考核使用新的活动 ID。

## 独立资料与题库

资料和题目通过关联表连接多个章节，后台可先创建未归类草稿；学习活动引用时校验章节、所属教师、就绪/审核状态及班级开放权限。资料的必读状态与条件分别保存在每个关联章节。题目source_type仅ai_generated/imported；后台录入归入imported，source可选记录材料与页码，不凭空生成引用。题目状态draft/ready/disabled分别表示待审核/可用/停用；AI生成题目必须先审核，不将管理入口等同于已配置真实生成服务。

题目与活动的关联、顺序只保存在ActivityQuestion，学生提交与成绩仍按用户/班级/活动/题目隔离。章节、资料、题目和活动使用下述影响预览与二次确认流程，从当前教学中移除内容，保留学生历史证据；旧直接删除入口返回409，不能跳过预览。

## 资料逐页讲解与音频

本节拥有资料逐页讲解的生成、审校、失效、校准、音频与学生可见性规则。实现位于 `backend/app/narration/`，接口见[HTTP契约](api-contract.md#资料逐页讲解与音频)，模型与TTS配置见[开发手册](development.md#资料讲解与语音合成)。

仅 PDF 与演示文稿支持逐页讲解，视频、文本和其他类型不显示创作入口，教师 API 拒绝这些类型。学生端整份资料没有有效音频时隐藏播放区；已审校文字仍可作为授权阅读助教上下文。

**生成**只能由教师在后台显式触发，翻页、播放、阅读、学生浏览均不调用模型。讲解的输入是**整理稿**（见下节；没有整理稿的页不做讲解），不再逐页发页图，也不再拼接前几页讲稿：每 4 页一窗，一次调用写 4 页口播稿与小节锚点；口播稿用正式口语，亲切、清楚、不轻佻。输入由本窗整理稿、提示词版本与模型组成幂等键，输入不变不重复计费；窗口内页号必须与输入完全一致，缺页/多页整窗失败，已完成的其他窗口保留。单页入口仍可用于补写一页，走同一套窗口提示词。讲解稿只使用正文：`anchors` 必须是本页真实出现过的原文，生成后按整理稿（无整理稿时按原文）校验，对不上的锚点直接丢弃；`bridge_in` 已取消，不再生成也不再下发给学生。

**整理原文**（`POST .../narrations/digest`，后台 4 页一窗）：先把抽出来的原文整理成「整理稿」，再谈讲解。整理稿存 `page_contents`，原始解析文本仍在 `materials.content` 不动，重传课件不会覆盖整理结果。只允许识别层面的修正——错字、断行断词、顺序串行、重复序号、乱码；不改写、不扩写、不删知识点，拿不准就保留原样。每页同时产出 `title`（本页主题标题）、`topic`（一句话主题）、`tags`（内容页 2–6 个知识标签；封面、目录、致谢这类信息页可以为空）。因为整理稿是后续校准、讲解稿与 RAG 的唯一来源，发图阈值最宽：文本不足 600 字就附页图，页图渲染失败按该页失败处理，不静默退化成纯文本整理；每页记录 `image_state`（sent/policy/skipped/render_failed），缺图必须可见。页号必须与输入完全一致，缺页/多页整窗失败、不写半截；整理稿按页幂等，再次触发只处理原文变了的页，未变时零模型调用。整理的 `tags` 是页级原始标签，整册归并与课程级字典由后续校准处理。

**整册校准**（`POST .../narrations/calibrate`，后台逐窗）校对的是整理稿与原文：每窗给 4 页整理稿、对应原文与前后页，碎片页附页图（与整理同口径）。它只做两件事：① 输出 `fixes`——整理稿里确实有识别错误的页，给出修正后的完整整理稿；② 输出 `issues`——原文本身可疑、前后页矛盾、术语不一致等，只报告不改。`fixes` 落库前过机械闸门（长度差 ±30%、与原整理稿相似度 ≥0.6），改动过大的建议降级为 issue，避免把「校对」做成「重写」。最后对整册标签做一次归并：模型给出「别名 → 标准名」映射（只合并同义或写法差异，不合并上下位与并列概念），写入课程级字典，报告给出 `tag_stats`。应用报告只改整理稿（保持 draft，学生仍看不到）与标签字典，原始解析文本永不改写；报告生成后整理稿被改过的修正会被拒绝。

**讲解长度按页面性质分级**（提示词 `narr-v7`）：封面、目录、章节过渡、致谢这类信息页 80–140 字，只点题和承接；正常内容页 260–320 字，硬上限 340；代码或图表密集页可用到 340 字，但只讲 2–3 个关键点。这些是提示词里的软目标，**没有下限、不补写**：页面本来没内容就允许短，凑字数只会让讲解变啰嗦。校名、院系、课程号、教师姓名、邮箱、日期、页码、页脚、水印、校徽、背景图一律不念也不描述，封面页上这些信息整页跳过；全页最多出现一次“看中间这行”这类指位描述。

**状态**为 draft/accepted/rejected，另有由页文本、上传文件 SHA256、文件键与预览键共同校验的 stale，以及无文本且无页图的 unavailable。学生可见性与音频合成使用同一个门控：只有 accepted 且未 stale 的讲解生效。原文、纯图片文件或转换预览改变均令旧审校失效，需重新生成或改写正文后重新接受；不接受在原文已变的情况下继续放行旧讲解。学生播放器不展示来源/审校状态标签；讲解仍不计入阅读完成与学习证据，服务端保留审校门控。

**窗口衔接**：同一窗内的页共享上下文，模型知道前面一页刚讲过什么；跨窗不拼接已生成讲稿，避免模型复述上一窗而拉高重复率（实测相邻重复 1.3%）。回看/前瞻留了接口（`LOOKBACK_PAGES`/`LOOKAHEAD_PAGES` 与 `window_context()`），当前都为 0；若将来需要跨窗承接，改这两个常量和拼装函数即可，窗口版本号会让旧稿按新输入重新生成。

**一键梳理**（`POST .../narrations/pipeline`）：老师只点一次，后台按「梳理原文 → 整册校准 → 应用修正 → 生成讲解稿」逐段跑，每段完成后把剩余阶段写进任务进度，前端可显示三段进度条。校准报告自动应用（只改整理稿且保持 draft，原始文本不动）；审校页显示的正文就是修正后的整理稿，老师看正文时即能看到改动，不需另开报告。任何一段失败就停在那里并保留已完成产物，重试从失败段继续，不会重复计费已完成的整理与校准。

**审校页**显示的是整理稿正文，原始解析文本折叠在「查看原始文本」里；`title`、`topic` 与 `tags` 只读展示，不开放逐页手改：它们由整理与整册归并产生，手改会让旧讲解失效且无法规模化维护；确有系统性错标时修整理/校准规则。整理时没带页图的页显示「本页无图证据」，提醒老师内容可能缺图里的信息。校准报告列出 fixes 的前后对照与 tag 合并表，链会自动应用；老师看正文时看到的就是修正后的整理稿。

**助教上下文**优先读整理稿，未整理的页退回原始解析文本并用 `excerpt_source` 标注，避免把 OCR 噪声当成教材。

**竞态处理**：学生阅读沿用浏览器 PDF.js 渲染，所有页都能读取，无需按音频页向服务器反复请求图片；音频和字幕作为常驻附加控制区。翻页、换资料、换班与卸载时使旧音频请求失效并释放 URL，当前画布渲染完成后才允许播放。字幕保留 Python 空格，长句可换行。教师试听仍使用授权页图预取，旧页请求不阻塞新页。

**任务锁**：同一份资料同一时刻只允许一个生成／校准／音频任务。锁状态存在 `narration_jobs` 表
（每份资料一行），带心跳；心跳超过 5 分钟视为进程已死，允许下一次请求接管，避免崩掉的进程把资料
永久锁住。重复触发返回 409「这份资料正在处理中」，前端每 3 秒轮询任务状态并置灰全部触发按钮，
顶部显示“正在处理：生成 19/20”。任务结束（成功或失败）都会释放锁。首次占用锁定资料父行，工作者凭本次开始时间续租或释放，过期工作者不能关闭接管者的任务。批量生成、全篇校准与音频批量由后台 worker 执行，请求只入队并立即返回，教师可以切去别的资料；锁随整轮任务持有，不再按分片反复获取。校准逐窗续租；生成结果写回前核对资料指纹和讲解修订，教师新编辑优先。服务重启会把遗留的 running 任务标为 interrupted，再触发时从已完成窗口继续。

**提示词指纹**：幂等键包含提示词正文的哈希，改一个字也会让旧草稿失效并重新生成，避免“改了提示词
却复用旧讲解”。批量操作：`接受全部草稿` 一次接受范围内的 draft（可再单独驳回）；`批量合成音频`
只为已接受的页合成，已合成的复用、单页失败不影响其余页。

**审校界面**把预览和讲义合在一起：左栏是页码与状态，中间是这一页的页面图像（与生成时模型看到的页图一致，可上一下一页、跳页），右边是讲解稿、anchors、审校操作和音频试听。教师不必在“预览”和“审校”之间来回切换就能核对“讲的内容对不对、听起来怎么样”。页面图像通过带鉴权的接口取回（`<img>` 无法带 Bearer 头，前端走 fetch + blob）。

**整册校准**校对整理稿与原文，并归并整册标签（规则见上文「整理原文」之后的小节）。每窗最多 4 页，单窗文本预算 16000 字、单页整理稿最多 6000 字；长页整页发送，避免模型把发送方的预算截断误报成「原文缺内容」。文本层不足 600 字附渲染页图，图上限等于窗页数，需要图却没带上的页记入 `lost_images`；页图渲染失败记入报告并退回文本。整轮固定视觉模型。报告保存 fixes 与整册 `tag_map`；应用只改整理稿（保持 draft）和课程级字典，原始解析文本永不改写；报告生成后整理稿被改过的修正会被拒绝。

配图规则（2026-11-17 用一讲前 50 页实测后确定）：文本层不足 60 字视为碎片，改发渲染页图且不再附那段文本。整理与校准（校对整理稿）改用 600 字：中段页（60–199 字）漏图会让整理稿永久缺块，而整理稿是 RAG 与讲解稿的唯一来源。生成侧演示文稿不再无条件发图，同样按 60 字判断；PDF 生成暂保留 200 字阈值，等 60–199 档实验再定。依据：碎片页不发图时，校准会把讲对了的页报成 mismatch（第 4 页），发图后 3/3 条 mismatch 经页图核实成立（第 27、33、47 页）；演示文稿 ≥60 字的页只发文本与发图实质等价（第 6、22、37 页）。发图策略参与整册指纹，改阈值必须同时递增 `CALIBRATE_VERSION`。

校准是一次运行一行报告：未完成的报告带 `complete=false`，可查看进度但不能应用；已完成的报告不因后续运行而被覆盖。长资料逐窗推进，游标与合并结果逐窗落库，中断后再触发只跑剩余窗口；整册输入（提示词前缀、视觉模型、窗口参数、参与页修订、发图策略）未变时直接复用上次完整报告，零模型调用。任务在后台跑完，教师关闭审校页不影响进度；未完成时重复点击会被资料锁挡下（409）。

供应商只对“从第一个 token 起逐字相同”的前缀命中缓存，所以校准请求固定为：系统提示 → 校对要求与输出格式 → 材料名（以上整册不变）→ 上一窗尾部与本窗整理稿/原文/页图（可变），序列化固定。改动提示词正文、序列化方式或窗口大小都会使前缀缓存冷启动，写入报告前必须同步更新 `CALIBRATE_VERSION`。缓存命中的 token 数记录在报告 `usage` 中，用于核对收益；不得为了命中复用已失效的讲解。

**音频**只对 accepted 页合成，一页一份，键含讲解文本hash，正文改动即失效并避免复用旧录音；重新合成替换旧文件。音频不进入课程包，也不作为学习证据。当前音频永久保留、尚无过期清理，存储增长按课程与页数估算。

**学生提问**直接通过既有角色助教标签进入，删除功能重复的“就这页提问”入口；打开标签本身不发模型请求。发送问题后复用 create_agent、平台开关、角色、额度、压缩和持久会话；当前资料的已接受且指纹仍有效的讲解以明确标注的辅助资料进入本次请求的冻结上下文，支持原有全文检索与分段读取。草稿、失效稿、其他班级材料不进入上下文；练习工具范围不扩大。原独立 `/ask` 接口已移除，旧 narration_questions 历史表保留。

课程包现已携带各状态讲稿和匹配的已审校配音，见[交换契约](#课程包中的讲稿与配音)。已有导出目录需重新导出才包含后来生成的资源；不自动改写旧包或清理音频。

## 班级课程完整包设计

课程包交换教学内容、章节任务点与媒体。程序读取数据库与私有存储中的当前配置。导入预检只接受格式 4。组卷草稿可随课程包交换，导入后的学生测验依照随包发布的章节活动。

### 包目录与格式

目录包的 manifest.yaml 和 curriculum/course.yaml 均使用 schema_version 4。每章独立保存在 curriculum/chapters 下，资料、知识点、题目及私有答案存于 content，练习与测验存于 content/activities。资料的 task_points 为各关联章节记录 chapter_id、required、rule 和 order_index。每个章节关联恰有一项设置。角色、地图、答疑配置和班级开放安排由平台或班级维护。

### 课程包中的讲稿与配音

讲稿文件位于`narrations/<资料稳定ID的SHA-256>/pages.jsonl`，目录名经过哈希避免稳定ID包含文件分隔符；每行仍明确保存material_id稳定ID及page_no。字段包括text、bridge_in、target_seconds、status、source（teacher/ai_generated）、model、prompt_version、image_used、anchors、edited_by_teacher、reviewed_at、page_hash及可空audio。audio包含asset_id、text_hash、seconds，文件相对路径、格式、大小与SHA-256统一登记在assets/index.jsonl。支持WAV/MP3/OGG/Opus/FLAC/AAC/M4A，格式签名、哈希和引用均受校验。

所有讲稿状态原样携带；源页面已变化则导出为stale，保留正文但page_hash为空。只有accepted、页面仍匹配且音频对应当前正文时才携带音频；草稿/拒绝/过期讲稿不得携带可播放音频。已声明有效音频缺失或不可读会阻断导出，不静默生成不完整包。尚未合成或已因正文变化失效的音频不进入包，讲稿仍保留。当前字幕按正文分句推导，没有独立校准时间轴，无需重复导出字幕文件。

包内页面指纹由原页面与原始媒体、预览媒体的SHA-256组成，不包含服务器路径。导入按资料稳定ID及页码重建关联，再计算目标服务器的有效性指纹。审校状态和时间保留，但reviewed_by为空，不伪造目标服务器教师身份。音频写入目标课程独立私有路径，删除交换包或另一个班级重新合成不影响本班播放。凭据、学生对话、生成任务、调用日志和校准运行报告不属于交换内容。

差异预览显示逐页讲稿与配音变更；相同资料同页由包内条目更新，包内缺省的目标讲稿保留，资料变化仍按现行失效规则处理，不把无讲稿包当成清空指令。预览后讲稿、审校或音频发生变更需重新预览；进行中的讲稿/配音任务阻止交换，防止导入覆盖任务结果。导入和导出不调用模型，不重生成语音，不修改学生进度或成绩。

### 班级独立编辑与导入导出

本机记录新导出目录的导出者。教师管理个人导出包，旧目录与外部复制的目录继续作为共享包使用。默认包受保护，历史共享导出包由管理员删除。移除导出文件保留已建课程、学习记录和有效预览。

每门课程持有一份当前内容，开班直接引用课程。各班独立安排开放时间和暂停状态。

挂载的data/course为私有交换区，保存待导入包和导出产物；不是Web静态目录，也不是运行时第二份权威配置。整个data目录不进入Git或镜像，固定世界资源随程序发布；交换区挂载与维护见开发手册。上传读取、导出写入目录分权限管理，清理交换产物不得删除运行中私有媒体。

生命周期：选择目录→暂存→格式、资源、引用、章节任务及权限校验→差异与影响预览→教师确认→事务激活当前定义。运行时读取数据库与私有文件存储；后台编辑更新当前定义，显式导出再写包。直接修改挂载文件不自动生效；重启不导入。

目录列表只提供清单元数据；每次应用必须有新的有效预览，完整引用与媒体在预览阶段校验。具体操作见[开发手册](development.md#目录课程包操作)。

导入按包哈希、目标实例及请求ID去重；使用并发修订检查，预览后内容已变化则重新预览。先验证完整资源再激活，失败保留原课程，未引用暂存文件不对学生开放。导出读取一致的当前定义视图，避免并发编辑造成一半新一半旧；导出读一致性不等于保存教学内容历史版本。

同课程更新按稳定 ID 保留学习记录和成绩；可能破坏已分配题型、试卷或学习证据的变更在预览阶段阻断。

近期支持新班级导入、班内编辑、完整导出与同课程更新。有学习记录的班级直接换成另一门课程暂不支持；不能将旧成绩映射到新题或静默清档。后续若扩展需独立设计课程切换与历史访问规则。班级列表、导入/导出、文件下载和后台编辑均服务端授权，预览不授予写权限。

### 课程包验证边界

离线预检只验证清单与资源，不等同于完整导入。HTTP预览还需检查领域引用、章节条件、媒体、权限及学习影响，教师确认后才能应用。

课程或包格式变化按影响验证：跨班隔离、同包往返、重复导入幂等、并发/中断回滚、隐藏答案保护及学习证据保留。只改变对白或单项内容时选择相应专项，不自动触发完整后台重建验收。

旧格式不提供运行时兼容。数据库升级与私有目录转换见[开发手册](development.md#多资料活动升级)，不得套用任何历史测试环境的清空授权。

### 清单与资源预检契约

格式 4 必需 manifest.yaml、curriculum/course.yaml、assets/index.jsonl；无媒体时资源清单可以为空。manifest必填schema_version=4、package_id、name、字符串package_version、带时区created_at、requires和entry；updated_at/exported_at可选且按时间递增。origin可选为supplied（缺省，受保护）或exported（全站可删除，必须提供exported_at）；系统导出固定写入exported，复制包无需复制服务器私有状态。entry固定curriculum/course.yaml。requires为world_id=pythontopia-town、world_schema_version=1及不重复的capabilities列表，当前识别reading/video/practice/assessment/chapter_tasks/library。能力名称匹配只属于格式预检，不代表整包可执行。

资源清单每行一个JSON对象，必填id、path、media_type、size_bytes、sha256、source、license；path是assets内POSIX相对路径，sha256为64位小写十六进制。资源必须存在、清单完整、ID/路径不重复、大小和哈希一致，类型声明与支持的扩展名相符。清单预检不验证许可真实性。

默认限额：manifest及入口文本各512KiB、清单16MiB、单文件2GiB、总量8GiB、目录条目20000、资源10000、目录深度32。限制以PackageLimits集中定义，当前CLI不提供放宽参数。拒绝路径穿越、绝对路径、反斜杠、Windows特殊文件名、大小写路径冲突、符号链接/重解析点、重复键、YAML锚点/别名及未知字段。该独立CLI只证明清单与资源完整性；完整目录包导入另外执行解压安全、领域引用、章节条件、内容类型及本班学习影响检查。PDF/PPT等解析和转换采用受控处理器，真实转换服务的可用性需单独验证。

课程交换暂存副本自动回收。成功导入或预览过期后进入清理队列，正式导出目录与共享课程包由维护者管理；清理周期、残留识别及并发边界见开发手册。

平台维护固定地图与四个角色。管理员统一设置角色的名字、人设、立绘和像素形象，课程包只携带课程内容与所需私有媒体。

## Python 编程题

编程题使用统一题库的 `kind: python`，通过 ActivityQuestion 与普通题混排，不增加活动类型。采用标准输入输出；`prompt` 为题目描述，`samples` 为公开 input/output 用例，私有 secrets 保存 hidden_cases；`hints` 最多10条，每条1–2000字符，`starter_code` 最多20000字符。非编程题使用空提示和空初始代码。课程更新须显式预览并确认，不自动改写已导入班级。浏览器试运行不产生完成证据，正式提交由 go-judge 使用公开及隐藏用例评测。

## 级联删除与学生历史保留

四类内容采用同一流程：选择目标 → 服务端计算影响清单 → 教师查看“一起删除／解除关联／保留” → 点击「确认级联删除」。单次最多100个目标，批量整体成功或整体回滚。预览15分钟内有效；确认时重新核对课程修订及学生记录，发生变化要求重新预览。

| 删除目标 | 一起移除 | 解除关联与保留 |
| --- | --- | --- |
| 章节 | 所属知识点和活动 | 独立资料和题目保留，解除章节及知识点关联 |
| 资料 | 本资料的章节任务点 | 保留题库，解除资料来源引用 |
| 题目 | 删除后题集为空的活动 | 从其余题单解除关联，保留已交试卷和成绩 |
| 活动 | 该项练习或测验 | 保留章节资料和题库，解除活动选题关联 |

转换中的资料暂不可删除。超出教师管理权限的级联项会阻止确认。

删除将当前定义标记为已移除，默认管理、学习与导出查询不再返回；保留内容原行及历史所需私有文件，不释放原有稳定ID供新内容复用。同课程包重新导入已移除ID时列为阻断，新增内容须使用新ID；包更新试图硬删仍被历史保留定义引用的上级内容时，提示先用级联删除处理，再重新导入。学生提交、执行载荷/诊断、试卷与成绩、章节阅读证据和助教会话均保留，不重判、不重算。已交试卷所在活动仍可用时继续展示原题集；被移除活动退出当前教学，不增加学生“历史档案”页面。教师评测管理仍可查历史代码与诊断，学生只能读取自己的既有公开提交回执。


任务管理以每次任务为单位，分正在执行与历史记录，持续保留生成、校准和配音的执行人、范围、进度、时间和失败原因。重试新建记录，不覆盖原失败；批次保留成功页并只重试明确失败页。原任务锁继续防止同资料并发执行，过期心跳归为待核查；仅回填升级前实际保留的最后一次记录，不虚构被覆盖历史。已删除资料的执行记录仍可查，无法重新发起；查看/审校作为次要入口。界面与权限见[后台规范](design/teacher-interface.md#任务管理)。

### 题型与答案

统一题库支持单选（`single_choice`）、多选（`multiple_choice`）、判断（`boolean`）、填空（`fill`）和 Python 编程（`python`），均可用于练习与测验并混合选题。单选答案为选项字符串；判断为布尔值；填空为单个输入，私有答案可列出多种可接受写法，忽略首尾空白和大小写。

多选公开 `options` 为2–20个非空且不重复的字符串，私有 `answer` 为至少两个不重复、属于选项的正确答案；草稿允许未填完，设为可用时严格校验。学生答案为选中选项的字符串数组，顺序不影响评分，必须与正确答案集合完全相同，少选、多选及重复值均不通过；不设部分分。格式 4 课程包，以原生数组交换多选答案，旧版本程序不能导入新增题型。

### 交互练习题

`kind: interactive` 只用于练习。课程包在公开记录的 `interactive` 字段保存 HTML、CSS、JavaScript，在对应私有记录中保存正确提交值。教师可从内置的「点亮小镇路灯」或「整理采集背包」开始制作、查看助教状态并试答。接口用法、可直接粘贴的完整题目、沙箱限制及发布前试做步骤见[如何制作交互练习题](interactive-practice-authoring.md)。
