## 文档维护

- 需求或行为变化时修改对应正文；同一条规则只保留一处完整说明，其他文档用简短摘要和链接引用。API字段不复制到产品说明，操作命令不复制到内容规范。
- 需求保存稳定编号和约束，具体参数、界面细节及实现说明放在各自规范；已撤销决定不从旧代码、测试或历史记录恢复。
- 自有文档采用英文小写、连字符文件名和中文标题；README、AGENTS及许可、第三方来源文件保留惯例名称。不新建“建议文档”“续做入口”或逐轮报告，未定事项在对应规范中明确标为待定。
- 验证通过、失败、跳过和未覆盖范围在交付回复中如实说明。需要长期留存的测试、部署、备份和交接记录放在本地忽略目录，不纳入Git；公开文档不依赖这些记录。已有Git历史不改写。
- 影响使用的限制写在相关规范中；尚未重新验证的问题保留记录日期和不确定性，不将缺少复验误写为已修复，也不把旧通过结论视作当前保证。
- 文档修改检查事实、范围、链接及锚点，执行方式见[基础检查](development.md#基础检查)。只有相关实现变化时才运行对应功能测试，不因整理文档重跑全量。
